# 웹 앱 전환 설계 · 2026-10-13

이 문서는 기존 DEVELOPMENT_PLAN의 플랫폼·저장·인증·배포 방식을 대체한다. 거래, 정산, 빚, 정기 내역, 분류 문자열/ID, 시안블루 가변 UI와 하단 탭은 유지한다. 구현은 이 문서를 먼저 확정한 다음 진행한다.

## 결정 사항

- Flutter Web PWA를 GitHub Pages에 배포한다. Android Chrome과 Windows Chrome/Edge의 최신 버전을 대상으로 한다. APK·EXE·Inno Setup·배포 서명 키 없이 브라우저에서 설치한다.
- 각 기기에서 사용자가 선택한 내부 저장 폴더에 JSON을 저장한다. 폴더 선택은 브라우저의 권한 대화상자로 수행한다. 웹에서 임의의 절대 경로를 지정하거나 접근 권한을 우회하지 않는다.
- File System Access API 지원 여부를 실제로 검사한다. 지원하지 않는 브라우저에서는 가계부 입력을 시작하지 않고 지원 브라우저를 안내한다. Android의 지원 여부는 브라우저 버전 및 폴더 제공자에 따라 실기기 확인한다.
- 동기화는 앱을 새로 열었을 때 한 번, 사용자가 버튼을 눌렀을 때만 실행한다. 수정 직후, 일정 간격, 백그라운드, 단순 화면 복귀에는 동기화하지 않는다. 정기 내역은 실행/복귀 시 누락 회차를 로컬에 생성한다.
- Google Drive는 각 사용자의 Google 로그인과 선택 폴더를 사용한다. 개인 폴더 ID·토큰·가계부는 Git에 넣지 않는다.

## 저장 구조와 복구

SQL 집계와 업무 검증은 유지한다. 웹에서는 SQLite WASM 메모리 DB를 사용하고, 불변 변경 이력과 기기 설정을 폴더의 체크포인트로 저장한다. 시작할 때 체크포인트를 검증하여 SQL 조회 테이블을 재구축한다. Excel은 가져오기/내보내기에만 사용하며 동기화 원본은 JSON이다.

| 위치 | 내용 | 삭제/동기화 범위 |
| --- | --- | --- |
| 선택 폴더/ChagokLedger/owner.json | 앱 전용 폴더 식별자·형식 | 앱 소유 확인용 |
| checkpoint-0.json, checkpoint-1.json | 형식 버전, 세대 번호, JSON 본문, SHA-256; 본문에는 변경 이력·기기 설정·전송 완료 ID | 두 슬롯 교대 저장, 이 기기에서만 사용 |
| backups/ | 복원 직전 전체 백업 | 같은 앱 전용 폴더에서 관리 |
| 브라우저 IndexedDB | 폴더 핸들 | 폴더 재접속용, 가계부의 유일한 원본이 아님 |
| 브라우저 세션 저장소 | 만료 시각이 있는 단기 Google 액세스 토큰 | Drive·체크포인트·백업에 포함하지 않음 |
| Google Drive의 선택 폴더 | 가계부 메타정보·불변 변경 JSON | 기기 간 동기화; 로컬 삭제 시 유지 |

체크포인트는 이전 슬롯을 보존하고 반대 슬롯에 새 데이터를 기록한 뒤 close 완료를 확인한다. 저장 완료 전에는 ‘저장 중’, 실패하면 ‘기기 저장 실패’를 표시한다. 실패 상태에서는 추가 입력을 막고 재시도·전체 백업을 제공한다. 저장되지 않은 메모리를 저장 완료로 표시하지 않는다. 두 슬롯 중 정상인 최신 세대를 읽으며, 하나가 손상되었으면 이전 정상본을 복구했다는 안내를 표시한다. 둘 다 손상되었거나 알 수 없는 버전이면 새 빈 장부로 덮어쓰지 않는다. 체크섬은 우발적인 손상을 탐지하며 악의적인 변조를 막는 서명이 아니다.

동일 사이트의 두 탭은 Web Locks로 동시 사용을 막는다. 저장 전에 디스크의 세대를 확인하여 다른 실행 환경/외부 수정으로 최신 파일이 바뀌면 덮어쓰기를 중지한다. 선택 폴더를 별도 클라우드 드라이브 앱으로 동시에 동기화하는 것은 지원하지 않는다. 기기 간 병합은 Google Drive의 변경 이력 프로토콜만 사용한다.

Web Locks는 같은 브라우저 프로필·원본 안에서만 유효하다. 다른 브라우저나 외부 프로그램과의 동시 쓰기를 OS 수준에서 잠그지는 못하므로 한 로컬 폴더는 한 브라우저 프로필에서 사용한다. GitHub Pages의 같은 사용자 도메인 아래 프로젝트들은 같은 웹 원본이므로, 신뢰할 수 없는 앱과 같은 도메인으로 배포하지 않는다.

## 실행과 인증 흐름

1. 최초 실행: 브라우저 기능 확인 → 로컬 폴더 선택 → 앱 전용 하위 폴더 확인/생성 → 기존 기록 검증 또는 새 장부 생성.
2. 재실행: 기억한 폴더 핸들의 권한이 유효하면 바로 열기. 권한이 만료되었으면 ‘기존 폴더 다시 연결’ 클릭으로 권한을 다시 받는다.
3. Google 연결: 사용자 클릭 → Google Identity Services 토큰 팝업 → 계정 확인 → Drive 폴더 선택 → 기존 가계부 선택 또는 현재 장부 연결.
4. 새 앱 실행: 유효한 토큰이 있고 연결된 경우 동기화. 토큰이 없거나 만료되면 로컬 사용을 계속하고 ‘동기화하려면 Google 연결’ 안내. 자동 팝업을 띄우지 않는다.
5. 수동 동기화: 유효 토큰 재사용, 필요하면 사용자 클릭으로 토큰 재발급. 계정 힌트를 사용해 매번 계정 선택을 반복하지 않도록 한다. 선택 계정의 실제 Drive 소유자가 저장된 계정과 다른 경우 동기화 차단.

서버 없는 웹 앱에서는 장기 refresh token/클라이언트 secret을 안전하게 보관하여 영구 자동 로그인을 보장할 수 없다. Google 세션이 유효하면 비밀번호 입력 없이 승인할 수 있지만 Google의 정책·권한 철회·브라우저 팝업 제한에 따라 재확인이 필요하다. 단기 토큰은 세션에만 보관하고 만료 시 사용하지 않는다. 일반 폴더 탐색은 기존 `drive` 범위를 유지하며 동의 화면에서 광범위한 권한이 보인다는 점을 안내한다.

## 삭제·업데이트

PWA 제거와 사용자 선택 폴더의 삭제는 연결되지 않는다. ‘앱 제거 시 로컬 파일 자동 삭제’는 순수 웹 앱에서 보장할 수 없는 요구다. 대신 설정의 ‘이 기기의 데이터 삭제’를 사용한다. 미전송 변경 수와 삭제 범위를 확인하고, 앱 식별자가 일치하는 폴더의 알려진 가계부 파일·자동 백업만 삭제한다. 선택한 상위 폴더와 사용자의 다른 파일, Google Drive 기록은 삭제하지 않는다. 앱에서 내보낸 Excel/JSON 복사본도 자동 삭제 대상이 아니다.

GitHub Pages 새 배포 후 서비스 워커가 새 정적 파일을 준비한다. ‘업데이트 확인’으로 확인하고 현재 쓰기와 동기화를 마친 뒤 새 버전을 적용한다. 업데이트는 가계부 파일을 삭제하지 않는다. 앱 정적 파일만 오프라인 캐시하며 Google 인증/Drive 응답은 캐시하지 않는다. 다른 GitHub Pages 프로젝트의 캐시는 지우지 않는다. 최초 접속과 새 버전 다운로드에는 인터넷이 필요하다.

네이티브 생체인증 잠금/EXE·APK 자동 설치는 웹 배포 대상에서 제외한다. 기기 잠금으로 보호하며, 현재 JSON은 암호화되지 않는다. 서버 없는 잠금 화면을 데이터 암호화라고 표현하지 않는다.

## 구현 순서와 완료 기준

1. 본 전환 문서와 기존 기획의 모순을 정리한다.
2. 공통 SQL 저장소를 WASM과 연결하고, 로컬 파일 체크포인트·손상 복구·중복 실행 방지·안전 삭제를 구현한다.
3. 웹 Google 인증과 실행/수동 동기화만 허용하는 컨트롤러를 구현한다.
4. 폴더 연결, 저장 오류, 데이터 삭제, 웹 설치/업데이트 UI를 기존 가계부에 연결한다.
5. GitHub Actions의 웹 빌드·Pages 배포를 구성한다. 공개 `GOOGLE_WEB_CLIENT_ID` 변수만 사용하며 사용자 토큰이나 서명 secret을 요구하지 않는다.
6. 기존 금액/분류/정산/빚/정기/Drive 테스트, 웹 저장소 오류·복구·삭제 테스트, 정적 분석, 웹 release 빌드를 실행한다. 브라우저 렌더링 및 가능한 범위의 오프라인 검증을 수행하고, 실제 기기/Google 계정 미검증 항목은 구분하여 기록한다.
