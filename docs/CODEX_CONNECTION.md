# Codex에서 실제 내역 수정

Excel을 내보내거나 다시 가져오지 않고, 같은 Windows 기기의 Codex에서
가계부를 조회하고 기존 거래를 수정합니다. MCP 서버나 별도 계정은 필요 없습니다.
앱이 선택한 폴더의 파일을 통해 요청을 받고 기존 저장·검증·동기화 경로로 반영합니다.

## 처음 한 번 연결하기

1. 이 기능이 포함된 웹 앱으로 업데이트합니다.
2. 더보기 → 설정 → **Codex 파일 연결**에서 **로컬 파일로 내역 수정 허용**을 켭니다.
3. 앱이 사용하는 Windows 저장 폴더의 전체 경로를 Codex에 알려 줍니다.
   설정에는 브라우저 제한으로 전체 경로 대신 폴더 이름만 표시됩니다.
4. 수정하는 동안 앱을 열어 둡니다. 전면에 있는 동안 약 3초마다 요청을 확인합니다.
   백그라운드 탭은 브라우저에 의해 지연될 수 있고, 닫혀 있으면 다시 열 때 처리합니다.

이후에는 Codex에 변경할 내용을 말하면 됩니다. Codex는 최신 내역을 읽고 수정 요청을
기록한 뒤 앱의 저장 완료 응답을 확인합니다. 사용자가 매번 파일을 선택할 필요는 없습니다.
연결을 끄면 새 요청을 처리하지 않습니다. 다시 켤 때 연결 ID가 변경되므로 예전 연결의
대기 요청을 적용하지 않습니다.

수정은 먼저 이 기기에 저장됩니다. 다른 기기 반영은 기존 **지금 동기화** 동작을 따릅니다.
현재 연결은 일반 수입·지출·이동의 날짜, 메모, 금액, 계좌, 유형, 대분류·소분류 수정용입니다.
환불·이전 사람별 정산이 연결된 거래, 분할 지출, 잔액 조정, 마감된 정산의 원거래,
충돌 중인 거래는 거절합니다. 거래 추가·삭제, 계좌 생성, 빚·정기 규칙 수정은 이 프로토콜에서
지원하지 않습니다.

## Codex가 사용하는 명령

프로젝트 루트에서 Python 3로 실행합니다. `--folder`에는 선택 폴더,
`ChagokLedger`, 또는 그 아래 `codex` 폴더의 절대 경로를 지정할 수 있습니다.

```powershell
python scripts/ledger-connect.py --folder "D:\내 가계부" status
python scripts/ledger-connect.py --folder "D:\내 가계부" query --account "NH 농협"
python scripts/ledger-connect.py --folder "D:\내 가계부" apply --plan "D:\작업\수정계획.json" --wait 30
```

`query`의 최신 `ledger`, `connection`, 거래 `data.id`, `base`를 보존해 계획을 만듭니다.
계좌 이동의 `account`와 `destination`은 이름이 아닌 snapshot의 계좌 ID입니다.
예를 들어 아래 계획은 기존 지출 한 건을 지갑 이동으로 변경합니다.

```json
{
  "ledger": "snapshot의 ledger",
  "connection": "snapshot의 connection",
  "operations": [
    {
      "id": "수정할 거래 ID",
      "base": "검토한 거래의 base",
      "set": {"type": "transfer", "destination": "도착 계좌 ID"}
    }
  ]
}
```

분류 변경은 `{"category":"식비","subcategory":"식료품"}`처럼 지정합니다.
유형을 바꾸면 기존 분류는 초기화합니다. 수입·지출로 바꿀 때는 분류도 지정해야 합니다.
이동은 분류를 비워 둘 수 있습니다. 이름이 기존 분류와 일치하면 해당 ID도 연결합니다.
알 수 없는 필드는 거절하며, 원래 거래 ID와 가져오기키·정기 생성 메타정보는 유지합니다.

`applied` 결과만 기기 저장 완료를 의미합니다. `rejected`이면 한 건도 적용하지 않았으며,
사유를 검토하고 최신 snapshot으로 새 계획을 만들어야 합니다. `pending` 또는 응답 없음은
실패가 아니라 완료 여부가 아직 확인되지 않은 상태입니다. 같은 요청을 다시 보내지 말고
앱을 열어 둔 상태에서 `status`로 확인합니다. 앱 설정에는 파일 연결 오류도 표시됩니다.
정상 종료하지 못한 CLI가 `client.lock`을 남겼다면 다른 클라이언트가 실행 중이지 않은지
확인한 후 그 잠금 파일만 제거합니다.

## 파일 계약과 저장 보장

| 파일 | 작성자 | 의미 |
| --- | --- | --- |
| `ChagokLedger/codex/owner.json` | 앱 | 연결 폴더 소유 가계부 식별 |
| `snapshot.json` | 앱 | 거래·계좌·분류·정산과 거래별 기준 버전 |
| `request.json` | Codex | 한 번에 1~500건의 수정 요청 |
| `result.json` | 앱 | 요청 ID에 대응하는 적용 또는 거절 결과 |
| `ChagokLedger/backups/before-codex-*.json` | 앱 | 수정 직전 전체 장부 백업 |

- 요청은 `format: chagok-file-request`, `version: 1`, 고유 `id`, `ledger`,
  `connection`, `operations`를 포함합니다. 크기는 1MiB 이하입니다.
- CLI는 임시 파일을 완성한 후 `request.json`으로 교체합니다.
  처리 중인 요청을 덮어쓰지 않으며, 동시에 여러 작성자를 사용하지 않습니다.
- 모든 거래의 기준 버전을 검사합니다. 백업을 기다리는 동안 앱에서 내역을 바꾸어도
  다시 검사하여 오래된 요청으로 덮어쓰지 않습니다.
- 거래 변경과 처리 영수증을 하나의 SQL 트랜잭션에 기록합니다.
  앱의 교대 체크포인트 저장과 읽기 검증까지 성공해야 `applied` 결과를 게시합니다.
- 응답 파일 쓰기가 실패해도 저장된 영수증으로 재응답합니다. 같은 요청을 중복 적용하지
  않습니다. 실패한 체크포인트 저장은 기존 앱의 저장 실패 화면과 재시도를 따릅니다.
- 새 변경 이력을 생성하므로 잔액·통계·정산 합계 및 기존 Drive 동기화에 반영됩니다.
- **Codex는 `checkpoint-*.json` 또는 Drive 변경 파일을 직접 편집하지 않습니다.**
  해당 파일을 외부에서 덮어쓰면 기존 앱의 동시 변경 보호에 의해 저장이 중지됩니다.

연결 폴더는 평문이며, 그 폴더에 쓰기 권한이 있는 로컬 프로그램은 수정 요청을 넣을 수
있습니다. 신뢰하는 개인 저장 폴더에서만 연결합니다. 토큰·Drive 인증 정보는 snapshot으로
내보내지 않습니다. 이 기기의 데이터 삭제는 연결 파일과 자동 백업도 제거하며,
사용자가 별도로 만든 계획 파일은 삭제하지 않습니다.
