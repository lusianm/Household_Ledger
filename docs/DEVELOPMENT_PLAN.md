# 가계부 앱 개발 기획

> 2026-10-13 웹 전환: 플랫폼·저장·인증·배포의 상세 결정과 위험 검토는 [웹 전환 설계](WEB_TRANSITION.md)를 따른다.

사용자의 폴드 8 스마트폰, 가로형 안드로이드 태블릿, Windows PC에서 사용하는 개인 가계부를 만든다. 폴드의 접힘·펼침과 창 크기에 따라 배치를 바꾸고, 태블릿을 포함해 주요 탭은 하단에 둔다. Flutter Web PWA는 GitHub Pages로 배포하고, 같은 Google 계정의 Drive를 통해 기기 간 데이터를 동기화한다. 이 문서는 구현 전 기획이며, 화면 예시의 이름·인물·금액은 모두 가상이다. UI 가칭은 ‘차곡’이다.

## 1. 제품 방향과 범위

- Flutter / Dart로 Android Chrome과 Windows Chrome/Edge의 화면·금액 계산·데이터 모델을 공유한다.
- 인터넷 없이 입력·수정·조회하고, 앱 실행과 수동 버튼에서 동기화하는 로컬 우선 구조를 사용한다.
- 실제 계좌 잔액, 생활 수입·지출, 빚 원금, 정산 잔액, 적금 납입을 각각 구분한다.
- 최초 버전은 개인 사용자, 동일 Google 계정, 원화(KRW), 한국어, 가계부 시간대 Asia/Seoul을 기준으로 한다.
- 휴대폰·태블릿·PC는 HTTPS 웹 주소로 접속하고 브라우저의 앱 설치 기능을 사용한다. 배포 서명 키와 별도 설치 제작 도구는 필요하지 않다.
- 공유 가계부·은행 자동 수집·카드 문자 인식·다중 통화·투자 평가액은 후속 범위다. 기본 거래 입력, 계좌 관리, 카테고리, 통계, 정산, 빚, 정기 수입·지출·이동(적금 포함), Drive 동기화는 최초 정식 버전에 포함한다.

수입 예시 분류는 급여/월급·상여, 부수입/용돈·기타이며 지출은 식비/외식·카페·장보기, 주거/월세·관리비, 교통/대중교통·택시, 생활/생필품·통신, 여가/취미·구독, 의료/병원·약, 쇼핑 등이다. 이동의 기본 분류는 저축/예금·적금이다. 사용자가 수입·지출·이동 각각의 대분류·소분류를 추가·이름 변경·정렬·삭제할 수 있다. 설정과 내역 입력의 ‘카테고리 관리’에서 접근하며, 입력 도중 관리 화면에 다녀와도 금액·메모 초안을 유지한다. 같은 유형의 대분류 이름 및 같은 부모 아래 소분류 이름의 중복은 막는다.

삭제한 분류는 새 내역의 선택 목록에서 제외한다. 각 거래에는 기록 당시의 분류명을 문자열로 보존하며, 선택용 분류 목록에는 ID와 삭제 표시를 보존하여 과거 내역·통계·기존 정기 규칙이 유지되게 한다. 대분류 삭제 시 하위 소분류도 선택 목록에서 함께 제외한다. 기존 정기 규칙의 자동 기록은 계속 유지하며 규칙 편집 시 다른 활성 분류로 바꿀 수 있다. 입력 중 선택한 분류를 삭제하면 해당 선택만 초기화한다. 삭제와 동시에 다른 기기에서 기록을 추가한 경우에도 참조한 분류를 보존한다. 이름이 같은 새 분류는 새 ID로 취급한다.

기본 거래는 날짜·유형·금액·계좌를 필수로 받는다. 일반 수입·지출에는 대분류를 필수로, 소분류는 선택으로 한다. 이동에는 출발·도착 계좌가 필요하고, 이동 전용 대분류와 소분류를 선택적으로 지정한다. 정기 이동에도 같은 분류를 저장하여 회차 생성 시 복사한다. 기존 분류 없는 이동과 정기 규칙은 그대로 지원하며, 분류 지정 여부와 관계없이 이동은 수입·지출 통계에서 제외한다. 최근 선택값을 재사용하되 날짜와 금액을 명확히 보여준다.

‘내역 추가’의 상위 유형은 지출 / 입금 / 이동 / 빚 / 정기 내역이다. 빚은 빌린 돈·빌려준 돈 중에서, 정기 내역은 반복할 수입·지출·이동 중에서 선택한다. 모든 진입은 같은 금액·계좌 처리 규칙을 사용하며 특정 메뉴에서만 등록할 수 있는 구조로 제한하지 않는다.

금액·계좌·날짜·대분류·소분류를 한 화면에서 입력하고, 분류 바로 아래에 ‘메모 (선택)’라는 작은 한 줄 입력란을 둔다. 별도의 메모 전환 탭이나 거래명 입력란은 두지 않는다. 분류를 사용하지 않는 빚·정산 입금에서는 계좌·날짜 아래에 메모를 배치한다. 메모는 원거래와 정기 규칙에 저장하고 회차 생성 시 복사한다. 정기 내역에도 이름을 따로 입력하지 않으며 분류·계좌·메모로 구분한다. 내역 목록에는 ‘식비 › 카페’처럼 분류를 제목으로, 메모를 보조 설명으로 표시한다. 이동은 출발·도착 계좌, 빚과 정산은 상대방과 거래 유형을 자동 표시한다.

대분류와 소분류는 두 개의 선택 컨트롤로 분리한다. 먼저 대분류 ‘급여’를 고르고, 필요할 때만 소분류 ‘월급’을 고른다. 소분류 미선택은 정상 상태이며 통계에는 ‘소분류 없음’으로 묶는다. 대분류를 바꾸면 기존 소분류를 해제하고 새 대분류의 하위 항목만 보여준다. 메모 작성과 기기 접힘·펼침 중에도 입력 초안은 유지한다.

앱에서의 분류 입력은 위 선택 방식으로 유지한다. 저장할 때 선택한 대분류·소분류 이름을 거래의 문자열 필드에 복사하고, 해당 카테고리 ID도 함께 저장한다. 문자열 저장을 위해 일반 입력 화면을 자유 입력 방식으로 바꾸지 않는다. 카테고리 목록의 이름을 바꾸어도 과거 거래에 저장된 이름은 바뀌지 않는다.

## 3. 금액 집계 규칙

‘입금’이라는 은행 방향과 ‘수입’이라는 통계 의미를 분리한다. 금액은 부동소수점이 아닌 원 단위 정수로 보관하며, 거래 유형이 통계 포함 여부를 결정한다. 사용자가 임의의 수입 제외 플래그만 붙여 잔액과 정산이 분리되는 구조는 사용하지 않는다.

### 자산 표시와 빚의 관계

홈의 ‘계좌 합계’는 보유 현금·은행·저축 계좌 잔액 합계다. 빌려준 원금, 받을 정산금을 자산에 더하지 않고, 별도 빚 장부의 빌린 원금도 이 합계에서 차감하지 않는다. 사용자의 요청에 맞춘 표시 방식이므로 이 수치를 ‘순자산’이라고 부르지 않는다.

홈 상단은 ‘내 전체 잔액 / 지금 쓸 수 있는 돈 / 이번 달 수입 / 이번 달 내 지출’을 표시한다. 전체 잔액에는 적금을 포함하고, 사용 가능한 금액은 사용자가 유동 계좌로 지정한 입출금 계좌와 현금의 합계로 한다. 미래 수입, 아직 받지 않은 정산금, 빌려준 원금은 사용 가능액에 포함하지 않는다. 사용 가능액은 이미 예정된 지출까지 차감한 금액이 아니므로 예정 출금과 별도로 보여준다. 예산 잔여액은 자산 잔액과 혼동하지 않도록 별도 지표로 둔다.

실제 돈이 입출금되면 해당 계좌 잔액은 변한다. 예를 들어 100만 원을 빌려서 은행 계좌에 받았다면 은행 잔액은 100만 원 늘지만 수입은 늘지 않는다. ‘빚을 자산에 포함하지 않는다’는 요구는 빚 장부의 잔액을 별도로 가감하지 않는다는 의미로 정의한다.

이미 실제 잔액에 반영된 과거의 빚을 옮겨 적을 때는 ‘기존 빚만 등록’을 기본값으로 사용한다. 새로 발생하는 대여·차입은 ‘계좌 입출금 함께 기록’을 선택하며, 계좌 원장과 빚 원장을 한 번에 저장한다. 빚 상환도 이 구분을 유지한다.

신용카드는 결제 사용 시 지출을 인식하고 카드 미결제액을 늘린다. 카드대금 납부는 은행에서 카드로의 이동으로 처리하여 지출이 두 번 잡히지 않는다. 카드 미결제액은 별도 표시하며 ‘계좌 합계’에 양수 자산으로 더하지 않는다. 카드 한도는 자산이 아니다.

## 4. 정산 상세 흐름

1. 지출 입력에서 ‘함께 쓴 돈’을 켜고 총 결제액 90,000원, 내 몫 30,000원, 민수 30,000원, 지연 30,000원을 입력한다.
2. 균등 분할 또는 직접 금액을 지원한다. 총액과 개인별 몫의 합이 같아야 저장한다. 나누어떨어지지 않는 원 단위 차액은 본인 몫으로 배정하고 저장 전 보여준다.
3. 계좌에서는 90,000원이 빠지고, 식비 통계에는 본인 몫 30,000원만 반영한다. 정산 화면에는 상대방별 받을 금액이 생긴다.
4. 민수 옆 ‘받음’을 누르면 미수령 잔액, 입금 계좌, 날짜가 미리 채워진다. 전액 또는 일부 금액을 저장한다.
5. 10,000원만 받았다면 민수 잔액은 20,000원이 된다. 수입 통계는 그대로이고 실제 계좌에는 10,000원이 더해진다.
6. 일반 ‘입금’ 화면에서도 ‘정산금 받기’를 선택하고 기존 정산 대상과 연결할 수 있다. 양쪽 경로는 동일한 처리 함수를 사용한다.

정산 그룹에는 총 결제액, 내 부담, 청구 총액, 수령 총액, 남은 금액을 보여준다. 한 사람에게 여러 건이 있으면 사람별 합계와 건별 기록을 함께 제공한다. 이미 기록한 입금과 연결하는 경우 기존 거래 유형을 변경하며 새 입금을 중복 생성하지 않는다.

부분 수령·여러 번 수령·수령 취소를 지원한다. 초과 수령은 막고 잔액을 알려준다. 원지출을 수정하거나 취소할 때 기존 수령 내역을 함께 검사하고, 이미 받은 금액을 임의 삭제하지 않는다. 받지 않기로 한 금액은 ‘내 부담으로 전환’이라는 명시적 처리로 지출에 반영하고 변경 기록을 남긴다. 원지출 월의 통계가 바뀐다는 점을 적용 전에 표시한다.

월간 기본 통계는 결제일에 본인 부담을 인식한다. 실제 현금 유출입은 별도 필터로 볼 수 있다. 월말 결제 후 다음 달에 정산금을 받아도 두 달의 생활 수입·지출이 왜곡되지 않는다. 정산 지출이 여러 분류에 걸치면 내 몫과 상대방 몫을 분류별로 배분한다.

## 5. 빚 상세 흐름

‘빌려준 돈’과 ‘빌린 돈’을 나누고 상대방, 최초 원금, 발생일, 기한(선택), 메모를 기록한다. 잔액은 최초 원금 + 추가 원금 - 상환으로 계산한다. 한 상대방에 여러 약정을 둘 수 있다.

- 일부 상환·추가 대여·완료·상환 취소를 지원한다.
- 원금과 이자는 별도로 입력하며 원금은 생활 수입·지출에서 제외한다.
- 기한 경과는 앱 안에서 표시하고 알림은 선택 사항이다.
- 빚 장부와 정산 장부는 별도로 유지한다. 동일한 상대방을 재사용할 수 있어도 정산 잔액을 빚에 중복 등록하지 않는다.
- 원장 삭제보다 취소 이벤트를 우선해 잔액 계산과 기기 동기화에서 이력을 보존한다.

## 6. 정기 수입과 지출 및 이동 상세 흐름

하나의 ‘정기 내역’ 화면에서 **수입 / 지출 / 이동**을 모두 등록한다. 급여·용돈·연간 상여 등은 수입, 월세·구독료 등은 지출, 적금·정기 저축 등은 이동이다. 반복이라는 성격은 원거래 유형과 별도이므로 정기 항목을 모두 지출로 취급하지 않는다. 정기 수입과 고정 적금도 최초 정식 버전에 포함한다.

공통 등록 항목은 반복할 거래 유형, 금액, 월간/연간 주기, 첫 기록일, 종료일·만기일(선택), 메모, 자동 기록 여부다. 별도 이름 입력은 두지 않는다. 수입은 입금 계좌와 수입 대분류·선택적 소분류, 지출은 출금 계좌/카드와 지출 분류, 이동은 서로 다른 출발·도착 계좌를 지정한다. 최초 버전은 고정 금액 자동 기록을 지원하고, 변동 금액은 회차를 ‘금액 확인 필요’로 만든다.

정기 규칙 등록만으로 잔액·수입·지출을 바꾸지 않는다. 예정일에 생성된 실제 원거래를 한 번 반영한다. 이미 수기로 입력한 급여·월세 등이 있다면 해당 회차와 연결하여 중복 생성하지 않는다. 정기 수입 역시 자동 기록과 은행의 실제 입금 확인을 구분한다. 예정일 이전의 수입은 현재 잔액에 더하지 않는다.

적금 납입은 자산이동이다. 생활비 잔액은 줄고 적금 잔액은 같은 금액만큼 늘며, 생활 지출·수입·계좌 합계는 변하지 않는다. 적금 계좌도 내 계좌 목록과 자산 합계에 포함한다. 같은 계좌로의 이체는 금지하고 연결된 두 원장 기록은 한 번에 저장·수정·취소한다.

적금에는 만기일(선택), 목표 금액(선택), 납입 회차, 누적 납입액, 남은 예정 회차를 표시한다. 납입 누계와 계좌 잔액은 중도 인출·초기 잔액·이자로 달라질 수 있으므로 동일한 수치로 간주하지 않는다. 최초 등록 시 이미 납입한 금액은 초기 잔액 또는 과거 기록으로 명시하여 중복 납입을 만들지 않는다. 만기 반환 원금은 계좌 이동이고 실제 지급받은 이자만 이자 수입으로 기록한다.

- 매월 31일은 해당 월에 31일이 없으면 말일로 처리하되 다음 달의 기준은 계속 31일이다.
- 매년 2월 29일은 평년에 2월 28일로 처리하고 윤년에는 다시 2월 29일을 적용한다.
- 발생 기준은 가계부 시간대와 현지 달력 날짜다. 기기 시간대가 달라져도 회차가 바뀌지 않는다.
- `정기항목 ID + 예정일`을 유일한 회차 키로 사용한다. 재실행·재동기화·여러 기기의 동시 생성에도 한 건만 남는다.
- 앱 실행/복귀 시 먼저 누락된 지난 회차를 생성하고 잔액과 통계를 갱신한다. 지원되는 백그라운드 작업은 보조 수단이다.
- 앱이 종료된 정확한 시각에 반드시 실행된다고 약속하지 않는다. 기록의 거래일은 실행일이 아닌 원래 결제 예정일이다.
- 자동 생성은 장부 기록이다. 실제 은행 결제를 실행하거나 결제 성공을 확인하는 기능이 아니다. ‘자동 기록’과 ‘실제 결제 확인’을 구분한다.
- 회차를 지우거나 건너뛰면 처리 표시를 보존하여 다음 실행 때 재생성되지 않게 한다.
- 금액 변경은 적용 시작 회차부터 유효하고, 과거 완료 내역은 그대로 보존한다. ‘이번 회차만 수정’과 ‘이후 회차 수정’을 구분한다.
- 일시중지·해지 이후는 생성하지 않는다. 소급 시작일은 생성될 건수와 합계를 먼저 보여준다.

‘월평균 고정지출’, ‘이번 달 정기 적금’, ‘이번 달 필요한 출금액’을 구분한다. 예를 들어 월세 600,000원 + 통신 45,000원 + 음악 구독 10,900원, 연간 서비스 24,000원이면 월평균 고정지출은 657,900원이다. 연간 서비스가 결제되는 달의 실제 고정지출 예정액은 679,900원이다. 매월 적금 500,000원을 더하면 해당 월 생활비 계좌에서 필요한 총 출금액은 1,179,900원이다. 월세 600,000원을 이미 기록했다면 남은 출금 예정액은 579,900원이다. 적금은 준비할 돈에는 포함하지만 지출 통계와 생활비 예산 소진에는 포함하지 않는다.

여기에 ‘월평균 정기 수입’과 수입·지출·이동별 필터를 추가한다. 정기 수입 예정액으로 출금 예정액을 무조건 상계하지 않고, 입금일과 출금일 순서를 함께 보여준다. 계좌별 자금 전망에서는 그 계좌로 들어오거나 나가는 이동도 반영하지만, 전체 계좌 합계 전망에서는 내부 이동을 상쇄한다. 연간 수입·지출의 월평균 환산액은 분석용이며 실제 원거래는 연간 발생일에만 생성한다.

연간 비용을 12로 나눈 값은 분석용이며 매월 가짜 지출을 생성하지 않는다. 계좌별 출금 예정액은 출발 계좌를 기준으로 집계하고, 카드 청구 납부와 카드 이용 예정액은 따로 보여 중복 계산하지 않는다. 적금 자동이체도 실제 은행 송금을 실행하는 기능이 아니라 가계부 원장의 자동 기록이다.

## 7. UI 구성

### 폴드 8 스마트폰

하단 메뉴는 홈 / 내역 / 계좌 / 통계 / 더보기의 다섯 항목이다. 정산·빚·정기 내역은 더보기와 홈 바로가기에서 접근한다. 전체 잔액과 사용 가능액은 이번 달 수입·지출과 함께 홈 상단에 유지한다. 내역 추가는 어느 화면에서나 상단 버튼으로 접근한다.

접힌 커버 화면은 한 열, 펼친 내부 화면은 사용 가능한 폭에 따라 두 열로 구성한다. 넓은 화면에서는 거래 목록과 상세 정보, 정산 목록과 받은 돈 입력을 나란히 둔다. 접으면 선택한 상세를 이어서 보여주고 뒤로 가기로 목록으로 돌아간다. 입력 중인 금액·날짜·분류·메모와 선택 내역·계좌 필터·스크롤 위치를 접힘 전환, 회전, 창 크기 변경, 프로세스 재생성에 걸쳐 보존한다.

폴드 8을 우선 검증 기기로 삼되 물리 해상도나 모델명 하나로 화면을 고정하지 않는다. Flutter LayoutBuilder와 MediaQuery의 실제 가용 크기·DisplayFeature 정보를 사용하며, 접힘 경계가 보고되면 주요 버튼과 입력 필드가 그 영역에 걸리지 않게 한다. 가용 폭 600 논리 픽셀 미만은 한 열, 600~839는 두 열을 우선 검토하고 840 이상은 여유 있는 두 열을 쓰는 초기 기준을 두되 실제 글자 크기·화면 줌·멀티윈도우에서 조정한다. 이 수치는 폴드 8의 확인된 화면 규격이 아니다. 미리보기의 ‘폴드 접힘/펼침’은 대표 폭의 배치 시뮬레이션이며 실기기 검증을 대신하지 않는다.

입력은 한 화면에 집중시키고 금액·계좌·분류 순서로 배치한다. 입금에서는 일반 수입·정산 받기·원금 회수를 구분한다. 주요 조작은 터치 영역 최소 44px 수준을 확보하고 색상 외에도 수입·지출·이동·정산 라벨을 사용한다.

### 태블릿

가로 사용을 기본으로 하며 하단에 동일한 다섯 탭을 둔다. 좌측 탐색 레일로 바꾸지 않는다. 본문은 요약 지표와 두 개의 패널로 구성하고, 내역 목록·선택 상세 또는 분류 그래프·소분류 그래프를 나란히 보여준다. 하단 탭은 안전 영역 위에 두고 선택 상태를 보존한다. 키보드가 올라오면 입력 영역을 가리지 않도록 조정하며, 분할 화면·좁은 창에서는 한 열로 재배치한다. 가로 우선 설계는 회전·창 크기 변경을 막는다는 뜻이 아니다.

### Windows PC

기기 간 학습 부담을 줄이기 위해 주요 다섯 탭을 하단에 유지한다. 본문 상단에는 월 선택·필터·새 내역을, 중앙에는 목록과 분석을, 오른쪽에는 선택 항목 상세·수령 입력을 둔다. 키보드 입력, Enter 저장, Escape 닫기, 일반 검색 단축키를 제공한다. 긴 목록은 본문 안에서 스크롤하고 실제 앱의 하단 탭은 고정한다. 기획용 미리보기는 대화 화면 높이에 맞춰 내용이 확장된다.

전체 강조색은 시안블루다. 밝은 청백색 배경과 시안 계열 선택 상태를 사용하고, 텍스트·버튼은 충분한 명암 차이를 유지한다. 어두운 테마도 지원한다. 지출 비중은 도넛형 원형 그래프와 이름·금액·비율 범례로 보여준다. 대분류를 누르면 소분류 원형 그래프가 열린다. 색상만으로 분류를 전달하지 않으며, 대분류만 지정한 거래는 ‘소분류 없음’에 포함한다. 전체 지출이 0이면 빈 상태를, 순환불로 음수 분류가 발생하면 원형 비율 대신 해당 환불액을 별도로 보여주어 잘못된 부채꼴을 만들지 않는다.

계좌 카드 클릭 → 해당 계좌 필터가 적용된 내역 → 선택 거래의 계좌별 증감·대분류·소분류·메모를 보여주는 흐름을 제공한다. 이동 거래는 출발 계좌 내역에 출금, 도착 계좌 내역에 입금으로 나타나되 원거래는 하나다. 계좌 필터 변경과 전체 계좌로 돌아가기를 제공하고, 그 계좌에서 새 내역을 열면 계좌를 미리 선택한다.

기획용 화면 예시는 폴드 접힘·펼침·가로 태블릿·PC 전환, 하단 탭, 원형 통계, 계좌별 내역, 거래·빚 등록, 대분류/소분류 선택과 추가·삭제, 분류 아래의 작은 메모 입력란, 수입·지출·이동의 정기 등록, 정산 일부 수령, 빚 상환, 정기항목 일시중지를 체험하도록 만든다. 새 거래와 계좌 잔액·원형 통계는 연결한다. 예시는 실제 계좌·Drive·결제와 연결하지 않는다.

## 8. 저장 구조와 동기화

웹의 SQL 조회는 SQLite WASM 메모리 DB로 처리하며, 원장은 사용자가 선택한 기기 폴더의 JSON 체크포인트로 보존한다. Flutter 화면 계층, 금액/규칙을 처리하는 도메인 계층, 저장소 계층, Google 동기화·인증 계층을 분리한다. 화면에서 잔액을 직접 갱신하지 않고 거래 처리 함수를 통해 원자적으로 저장한다.

| 데이터 | 역할 |
| --- | --- |
| Ledger / Settings | 가계부 ID, 기준 통화, 시간대, 스키마 버전 |
| Account / Category / Budget | 계좌와 유동 계좌 여부, 수입·지출·이동별 분류 ID·부모 ID·이름·정렬·삭제 표시, 월별 예산 |
| Transaction / Posting / Allocation | 거래 의미, 계좌별 증감, 기록 당시 대분류·소분류 이름 문자열과 선택적 연결 ID, 별도 메모, 본인 부담 |
| Person | 정산·빚에서 재사용하는 상대방 |
| Settlement / Share / Receipt | 정산 그룹, 사람별 청구액, 수령과 연결 거래 |
| Debt / DebtEvent | 빌린/빌려준 약정, 추가 원금·상환·취소 |
| RecurringRule / RuleRevision / Occurrence | 수입/지출/이동 유형, 입출금·출발·도착 계좌, 대분류·소분류 이름 문자열과 연결 ID·메모, 반복 정의, 만기·목표, 유효 시점별 규칙, 회차와 생성 거래 |
| ChangeEvent / SyncCursor / Conflict | 변경 ID, 기기 ID, 부모 버전, 적용 여부, 동기화 충돌 |

모든 동기화 대상은 전역 고유 ID를 가진다. 계좌 잔액과 정산 잔액은 원장으로부터 계산하며 캐시와 원장의 불일치를 검사할 수 있어야 한다. 초기 잔액과 잔액 조정은 수입·지출이 아닌 별도 유형이다.

### 분류 문자열과 집계용 ID

거래의 분류는 카테고리 목록을 조회하지 않아도 읽을 수 있는 문자열로 저장한다. 선택·필터·집계에는 별도 ID를 함께 활용한다. 분할 지출에서는 각 분류별 배분 항목에도 동일한 필드를 적용한다.

| 필드 | 저장 형식과 역할 | 예시 |
| --- | --- | --- |
| `category_name` | TEXT · 기록 당시 대분류 이름. 일반 수입·지출에는 필수 | `식비` |
| `subcategory_name` | TEXT 또는 NULL · 기록 당시 소분류 이름 | `카페` |
| `category_id` | 선택적 분류 참조 · 등록된 대분류와의 연결 | 식비의 고유 ID |
| `subcategory_id` | 선택적 분류 참조 · 등록된 소분류와의 연결 | 카페의 고유 ID |

앱에서 새로 선택한 분류는 이름과 ID를 한 번에 저장한다. 과거 기록 가져오기에서는 이름만 있고 ID가 없어도 저장할 수 있다. 소분류가 없으면 이름·ID 모두 NULL이며, 분류를 선택하지 않은 이동과 빚 원금·정산 입금은 네 필드 모두 NULL이다. 소분류 ID가 있으면 해당 부모 ID와 유형이 일치해야 한다. 기기별로 발급한 숫자 번호만으로 동기화하지 않고 전역 고유 ID를 사용한다. 성능을 위한 로컬 숫자 키는 별도로 둘 수 있다.

거래 목록·상세·내보내기는 저장된 문자열을 사용한다. 카테고리 이름 변경·삭제가 거래의 문자열을 덮어쓰지 않는다. 사용자가 거래 자체의 분류를 다시 선택하면 그 거래의 이름과 ID를 함께 바꾸고 변경 이력을 남긴다. 문자열만 있는 거래를 기존 분류에 연결하는 작업은 ID만 보완하며 원래 문자열은 유지한다. 정기 규칙에도 이름과 ID를 저장하고, 회차 생성 시 유효한 규칙 버전의 값을 복사한다. 규칙을 명시적으로 수정하기 전에는 분류 목록의 이름 변경이 규칙의 문자열이나 과거 회차에 전파되지 않는다.

기본 통계는 ID가 연결된 기록을 같은 분류로 묶는다. 따라서 ‘카페’를 ‘커피·음료’로 이름 변경해도 같은 ID의 금액은 한 그룹으로 집계하고, 통계의 그룹 제목에는 현재 분류명을 사용한다. 각 원거래의 표시는 기록 당시 이름을 유지한다. ID가 없는 내역은 유형·대분류 문자열·소분류 문자열을 기준으로 별도 그룹에 집계하고 ‘분류 연결 전’으로 구분한다. 대분류만 ID가 있으면 그 ID 안에서 미연결 소분류 문자열로 묶는다. 삭제된 분류와 미연결 분류도 총액에 포함하며, 이름이 같다는 이유로 서로 다른 ID나 미연결 그룹을 자동 합치지 않는다. 연결·재분류 전후에는 전체 금액이 같아야 한다.

### Excel·CSV로 과거 내역 추가

Excel(.xlsx)과 CSV에는 `날짜 / 유형 / 금액 / 계좌 / 대분류 / 소분류 / 메모`처럼 사람이 읽을 수 있는 열을 사용한다. 이동은 출발·도착 계좌 열로 구분한다. 카테고리 번호를 파일에 필수로 요구하지 않는다.

가져오기 미리보기에서 열을 연결하고, 거래 유형과 대분류·소분류 이름을 비교해 일치하는 분류를 찾는다. 비교용으로만 앞뒤 공백과 유니코드 표현을 정규화하고 원본 분류 문자열은 보존한다. 일치하는 활성 분류가 하나면 그 ID를 연결한다. 삭제·이름 변경된 분류 또는 후보가 여러 개인 경우는 사용자가 연결 대상을 고르게 하며, 임의 연결하지 않는다. 목록에 없는 이름도 문자열과 NULL ID로 가져올 수 있고, 미리보기에서 ‘새 분류로 등록’ 또는 ‘기존 분류에 연결’을 선택할 수 있다. 새로 등록한 분류는 이후 앱의 기존 선택 목록에 나타난다.

소분류 없이 대분류만 있는 과거 기록은 정상 입력이다. 일반 수입·지출의 대분류가 비어 있거나 공백뿐인 행, 소분류만 있는 행은 수정 대상으로 표시한다. 미리보기에는 가져올 건수·금액 합계·미연결 분류·오류 행·중복 후보를 보여주고 확인한 행만 한 번에 저장한다. 분류를 연결하지 않았다는 이유만으로 유효한 과거 내역을 버리지 않는다. 내보내기에는 기록된 분류 문자열을 그대로 제공한다.

### 앱 내부의 실제 테이블 배치

아래 표는 업무 스키마의 논리 설명이다. 현재 구현의 정확한 컬럼은 lib/data/ledger_store.dart의 schema가 기준이며, 변경 이력에서 SQL 조회 테이블을 재구축한다. 공통으로 동기화 대상 행에 `id`, `ledger_id`, `version_id`, `created_at`, `updated_at`, `deleted_at`을 둔다. ID·문자열·날짜는 TEXT, 원화 금액은 INTEGER이며 NULL은 값이 없음을 의미한다. 거래일은 가계부의 현지 날짜, 생성·수정 시각은 UTC로 기록한다. 숫자형 로컬 키를 추가하더라도 동기화에는 전역 고유 ID를 쓴다.

| 실제 테이블명 | 주요 업무 필드 | 역할 |
| --- | --- | --- |
| `ledgers` | name, currency, timezone, schema_version | 가계부 단위 |
| `accounts` | name, kind, is_liquid, is_archived | 계좌·현금·적금·카드 설정 |
| `categories` | type, parent_id, name, sort_order | 선택용 대분류·소분류 목록 |
| `transactions` | date, type, amount, memo, reversal_of_id | 한 번의 거래와 취소 연결 |
| `postings` | transaction_id, account_id, delta | 계좌별 잔액 증감. 이체는 두 행 |
| `transaction_allocations` | transaction_id, amount, category_name, subcategory_name, category_id, subcategory_id | 수입·본인 지출·분류를 선택한 이동의 분류별 금액. 이동은 통계에서 제외. 이름은 문자열, ID는 선택적 연결 |
| `people` | name, memo | 정산·빚의 상대방 |
| `settlements` | expense_transaction_id | 공동 결제 원거래 |
| `settlement_shares` | settlement_id, person_id, claimed_amount | 사람별 받을 정산금 |
| `settlement_receipts` | share_id, transaction_id, amount | 일부 또는 전액 수령. 수령 거래·계좌 입금과 연결 |
| `debts` | person_id, direction, opened_on, due_on, memo | 빌린/빌려준 약정 |
| `debt_events` | debt_id, type, principal_amount, date, transaction_id | 최초 원금·추가 원금·상환. 계좌 연결 거래 ID는 선택 |
| `recurring_rules` | current_revision_id, status | 정기 규칙의 고유 식별·활성 상태 |
| `recurring_rule_revisions` | rule_id, effective_from, type, amount, account_id, destination_account_id, category_name, subcategory_name, category_id, subcategory_id, memo, cycle, anchor_month, anchor_day, start_on, end_on | 적용 기간별 정기 수입·지출·이동 정의 |
| `recurring_occurrences` | rule_id, scheduled_on, rule_revision_id, transaction_id, status | 생성·건너뛰기 회차. rule_id + scheduled_on을 유일키로 사용 |
| `budgets` | month, category_id, amount | 월별 전체·분류별 예산 |
| `change_events` | change_id, device_id, base_versions, payload, checksum | 여러 행의 변경을 묶은 불변 기록 |
| `sync_state` | ledger_id, device_id, remote_cursor, last_success_at | 기기별 로컬 동기화 상태 |
| `sync_deliveries` | change_id, upload_state, applied_state, last_error | 기기별 전송 대기·반영 여부. change_id로 재적용 방지 |
| `conflicts` | entity_id, base_version_id, candidate_change_ids, resolution_change_id | 동시에 수정된 버전과 충돌 해결 이력 |

분류 문자열의 실제 저장 위치는 `transaction_allocations`다. 수입·지출에 분류가 하나면 한 행, 여러 분류로 나누면 여러 행을 저장한다. 분류가 있는 이동은 이동 금액과 같은 배분 한 행을 저장하고, 분류가 없으면 배분 행을 만들지 않는다. 앱에는 원거래와 합쳐 한 내역으로 보여주며, `transactions`에 같은 분류 필드를 중복 저장하지 않는다. 이 배치는 앞서 정의한 ‘거래에 문자열과 ID 함께 저장’의 물리 테이블 구체화다. 정기 규칙의 분류 문자열과 ID는 규칙 버전에 저장하고 회차 생성 시 배분 행으로 복사한다.

일반 지출은 거래 금액과 배분 금액 합계가 같고, 공동 결제는 거래 금액 = 본인 배분 합계 + 상대방 청구액 합계다. 정산금을 받을 때는 수령 거래·계좌 입금·수령 연결 행을 만들지만 수입 배분 행은 만들지 않는다. 빚 원금·이동·초기 잔액·잔액 조정에도 생활 수입·지출 배분 행은 없다. 취소·환불은 원거래 연결과 대응 증감으로 처리하며, 중복 통계 반영을 막는 별도 규칙을 적용한다.

계좌 초기 잔액도 `opening_balance` 유형의 거래와 posting으로 한 번 기록한다. `accounts`에 다시 초기 금액을 더하지 않는다. 잔액은 유효한 postings의 합계, 생활 수입·지출은 해당 유형의 유효한 allocations 합계, 정산 잔액은 청구액에서 수령액을 뺀 값, 빚 잔액은 원금 사건들의 합계로 계산한다. `sync_state`와 `sync_deliveries`는 해당 기기에서만 관리하며 다른 기기의 진행 상태로 덮어쓰지 않는다.

### Google Drive 운용

사용자 요청에 따라 숨김 앱 전용 폴더 대신, 각 사용자가 Google 계정에 로그인하고 내 Drive의 일반 폴더를 선택·생성하는 방식으로 변경한다. Google Cloud의 Web OAuth 클라이언트 ID는 앱 식별용 공개 설정이다. 개인 계정 토큰·폴더·내역은 GitHub 빌드 설정에 넣지 않는다. 기존 폴더 탐색을 위한 `drive` 권한은 Google에서 전체 파일 접근으로 표시되며, 실제 가계부 조회·업로드는 선택한 폴더와 차곡 파일로 제한한다. 상세 설정과 Google 검증 요건은 README를 따른다.

서로 다른 Google 계정 사이의 공동 편집은 이 구조에 포함하지 않는다. 첫 연결 시 폴더에 원격 가계부가 있으면 ‘불러오기’ 또는 ‘이 기기의 가계부 연결’을 명시하고, 현재 로컬 내역을 조용히 덮어쓰거나 섞지 않는다. 계정·폴더 전환은 기존 연결 해제 후 진행하며 새 계정·폴더에 현재 기록을 업로드할지 확인한다. 연결 정보와 이전 전송 완료 표시 초기화는 하나의 로컬 트랜잭션으로 저장한다.

단일 SQLite 파일 또는 전체 JSON 한 개를 매번 덮어쓰는 방식은 피한다. 거래 단위의 불변 변경 묶음을 고유 ID로 업로드하고, 모든 기기가 ID를 기준으로 중복 없이 적용한다. 네트워크 재시도로 Drive에 같은 내용을 가진 파일이 둘 생겨도 변경 ID로 한 번만 처리한다. 여러 엔터티가 함께 바뀌는 정산 수령 등은 하나의 원자적 변경 묶음이다.

Drive의 동기화 파일은 제안 형식 `change-{change_id}.json`으로 저장한다. 파일 안에는 `schema_version`, `ledger_id`, `change_id`, `device_id`, `created_at`, `base_versions`, `mutations`, `checksum`을 둔다. `mutations`에는 대상 테이블·행 ID·작업 종류·해당 버전의 행 데이터가 들어간다. 예를 들어 이동 한 건은 transactions 한 행과 postings 두 행을 같은 파일에 포함한다. 수신 앱은 파일 전체를 검증하고 의존 버전을 확인한 뒤 하나의 로컬 DB 트랜잭션으로 반영한다. Drive 자체가 업무 행의 병합이나 원자적 DB 처리를 제공하는 것으로 간주하지 않는다. 준비되지 않은 부모 버전은 수신 대기로, 서로 갈라진 버전은 충돌 검토로 처리한다. 수정·삭제도 새 변경 파일로 남기며 이전 파일을 덮어쓰지 않는다.

초기 가계부 메타데이터와 복구용 스냅샷은 별도 파일로 저장한다. 스냅샷에는 각 테이블의 행과 포함한 변경 ID 집합 또는 동등한 반영 범위를 기록하여 이후 변경의 누락·중복을 피한다. 스냅샷 시각 하나만으로 반영 범위를 판단하지 않는다. 파일명이나 기기 시각 대신 파일 내부 고유 ID와 버전 관계로 동일 변경을 식별한다. 여기의 JSON은 논리 내용이며, 저장 암호화 여부와 실제 파일 포장은 인증·보호·복구 기술 검증에서 확정한다.

동기화 기본 절차는 원격 변경 수신 → 로컬 트랜잭션으로 적용 → 미전송 변경 업로드 → 수신 상태 확인이다. 오프라인에서 서로 다른 거래를 추가한 경우 자동 병합한다. 같은 거래를 서로 다르게 편집했거나 삭제와 편집이 충돌하면 두 버전과 변경 전 버전을 보존하고 사용자에게 선택을 요청한다. 충돌을 해결하기 전에는 마지막 공통 버전의 집계를 유지하고 경고를 표시한다. 기기 시계에 따른 ‘마지막 저장 우선’만으로 금액 기록을 없애지 않는다.

기능 간 제약도 검사한다. 예를 들어 두 기기에서 동일 정산의 전액을 각각 수령 처리했다면 두 개의 독립 거래 ID여도 자동 합산해서 초과 수령을 만들지 않고 검토 대상으로 둔다. 정기결제는 회차 키가 같고 내용이 동일하면 병합하며, 규칙 버전이나 금액이 다르면 충돌로 남긴다.

삭제는 삭제 표시를 동기화하여 오래된 기기에서 되살아나지 않게 한다. 최초 버전에서는 동기화 변경 기록을 성급하게 삭제하지 않는다. 후속 압축 기능은 모든 등록 기기의 반영 여부 또는 명시적 기기 퇴역 절차를 확인한 뒤 구현한다.

상태는 최신 / 보내기 대기 / 오프라인 / 로그인 필요 / 충돌 확인 / 오류로 구분한다. 마지막 성공 시각과 미전송 건수를 보여주며, 새 실행 및 수동 버튼에서만 동기화한다. 복귀·저장 후·백그라운드에서는 동기화하지 않는다. 실패해도 로컬 저장은 유지하고 수동으로 재시도한다.

### 인증·보호·복구

웹 Google Identity Services를 사용하며 공개 클라이언트 ID만 배포한다. 유효한 액세스 토큰을 재사용하고, 만료 시 사용자가 동기화 버튼을 눌러 재연결한다. 서버 없는 구조에서 영구 자동 로그인은 보장하지 않는다.

JSON은 평문이며 기기 잠금으로 보호한다. 생체인증 잠금과 종단간 암호화는 이번 웹 버전의 기능이 아니다. 폴더 체크포인트에는 토큰을 넣지 않는다. 앱 제거 시 파일 자동 삭제는 보장할 수 없어 명시적 기기 데이터 삭제를 제공하며 Drive는 유지한다.

복원 전 자동 백업을 만들고 기본적으로 새 가계부 ID로 복원한다. 복구 및 오류 처리의 상세는 WEB_TRANSITION.md를 따른다.

## 9. 개발 순서와 완료 기준

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 1. 기획·기술 검증 | 화면 흐름, 집계 예제, 웹 인증·폴더 저장·PWA 시제품 | Android와 Windows에서 동일 계정의 선택 Drive 폴더의 데이터를 읽고 쓸 수 있음 |
| 2. 기본 가계부 | 계좌·분류·거래·초기 잔액·통계·예산·Excel/CSV | 수입/지출/이동/카드 납부/환불 금액 일치, 분류 문자열 보존·ID 연결·파일 가져오기, 오프라인 재실행 유지 |
| 3. 정산과 빚 | 분할·일부 수령·회수·취소·계좌 연결 | 아래 금액 검증 시나리오 통과 |
| 4. 정기 내역 | 수입·지출·이동의 월간·연간 규칙·회차·자동 기록·만기 | 미래 수입의 잔액 미반영, 말일/윤년/장기 미실행/건너뛰기/금액 변경/중복 생성, 적금의 지출 제외와 계좌 합계 불변 검증 |
| 5. 동기화와 복구 | 변경 병합·충돌·백업·새 기기 복원 | 두 기기 오프라인 입력·동시 수정·중복 재전송에서도 유실 없음 |
| 6. 배포 검증 | 폴드 가변 UI·가로 태블릿·하단 탭·PWA 설치·업데이트 안내 | 사용자 폴드 8 접힘·펼침·회전·글자 크기·분할 화면, 가로 태블릿, Windows에서 초안·선택 내역 보존 및 설치·업데이트 확인 |

정식 배포 전에 정산·빚·정기 수입·정기 지출·정기 이동(적금 포함)·Drive 동기화까지 완료한다. 단계별로 검토 가능한 내부 빌드를 만들되, 요청한 추가 기능을 나중으로 미루는 최소 버전으로 범위를 바꾸지 않는다. 일정은 실제 인증·동기화 시제품 검증 후 산정한다.

금액 검증의 핵심 시나리오는 다음과 같다.

1. 90,000원 공동 결제 → 내 지출 30,000원 / 미정산 60,000원 → 20,000원 수령 후 미정산 40,000원, 수입 변화 0원.
2. 100,000원 대여 → 40,000원 회수 후 빌려준 잔액 60,000원, 생활 수입·지출 변화 0원.
3. 계좌 A에서 B로 100,000원 이동 → 계좌 합계·월 수입·월 지출 변화 0원. 수수료가 있으면 별도 지출.
4. 12월 공동 결제의 정산금을 1월 수령 → 1월 수입 증가 없음.
5. 월 31일 반복과 연 2월 29일 반복 → 짧은 달과 평년에서 규칙대로 한 번 발생.
6. 두 기기의 동일 정기 회차 생성 → 해당 유형의 원거래 한 건. 같은 정산을 서로 전액 수령 → 충돌 검토.
7. 이미 잔액에 반영된 과거 빚을 등록 → 은행 잔액 변화 없음.
8. 카드 사용 시 지출 인식 → 카드대금 납부 시 추가 지출 없음.
9. 앱 업데이트·스키마 마이그레이션·백업 복원 → 거래 수, 계좌 잔액, 정산 잔액, 빚 잔액 일치.
10. 매월 적금 500,000원 → 생활비 -500,000원 / 적금 +500,000원, 생활 지출과 계좌 합계 변화 0원. 필요한 출금액에는 포함.
11. 두 기기에서 적금 같은 회차 생성 → 양쪽 계좌 이동 한 쌍만 반영. 만기 이후 납입 중지, 만기 원금 반환은 이동·이자만 수입.
12. 다음 달부터 월급 3,200,000원 반복 등록 → 현재 잔액·이번 달 수입은 그대로. 예정일 회차 생성 후에만 수입과 입금 계좌에 한 번 반영.
13. 대분류 ‘식비’와 소분류 ‘카페’ 선택 후 대분류를 ‘교통’으로 변경 → 소분류 초기화. 소분류 미선택으로 저장하고 ‘소분류 없음’ 통계에 반영.
14. 금액·분류·메모 입력 중 폴드를 접고 펼침 → 초안 유지. 선택한 계좌와 거래도 유지하며 입력을 중복 저장하지 않음.
15. 적금 계좌 클릭 → 해당 계좌의 이동 입금 표시. 같은 원거래를 생활비 계좌에서 조회하면 출금 표시. 전체 잔액은 동일.
16. 수입·지출 대분류와 소분류 추가 → 입력에서 즉시 선택 가능. 중복 이름은 거부. 소분류 없이도 저장 가능.
17. 사용한 분류 삭제 → 새 입력에서는 숨겨지지만 과거 내역·통계·정기 규칙은 유지. 대분류 삭제 시 하위 선택도 제거. 관리 화면 복귀와 접힘 전환 후 금액·메모 초안 유지.
18. 거래명 없이 금액·계좌·대분류만으로 일반 내역 저장. 메모가 있으면 목록의 분류 아래와 상세에 표시. 정기 내역도 별도 이름 입력 없이 등록 가능.
19. ‘식비 / 카페’ 선택 후 저장 → 이름 문자열과 ID가 함께 기록됨. 목록의 ‘카페’를 ‘커피·음료’로 변경해도 원거래·내보내기에는 ‘카페’가 남고 같은 ID의 통계는 합산됨.
20. Excel/CSV의 미등록 분류명을 가진 과거 내역 가져오기 → 문자열 보존·ID 미연결 상태로 저장 및 집계. 이후 ID를 연결해도 원래 문자열과 전체 합계 유지.
21. 같은 이름의 다른 ID, 수입·지출에 각각 있는 같은 이름, 다른 부모의 같은 소분류, 삭제된 분류의 재등록 → 잘못된 자동 연결·합산 없음. 미연결·삭제 분류의 금액도 통계 총액과 원장 합계에 포함.

## 10. 배포와 자료

GitHub Pages에는 앱의 정적 코드만 배포한다. 개인 내역을 GitHub에 저장하지 않는다. GitHub Actions에서 웹 빌드를 검사하고 Pages에 배포한다. 공개 GOOGLE_WEB_CLIENT_ID 변수만 사용하며 Android 서명·Desktop OAuth secret은 웹 빌드에서 사용하지 않는다.

배포·삭제·인증의 한계와 위험 대응은 [웹 전환 설계](WEB_TRANSITION.md), 실제 검증 결과는 [구현 검토](IMPLEMENTATION_REVIEW.md)에 기록한다.
