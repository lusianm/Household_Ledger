# 구현 검토 기록

2026-10-13. [웹 전환 설계](WEB_TRANSITION.md)를 먼저 작성하고 기존 기획의 플랫폼·인증·저장·배포 내용을 수정한 후 구현했다. 사용 방법과 배포 설정은 [README](../README.md)를 따른다.

## 반영 범위

- 기존 Flutter 가변 UI, 하단 탭, 시안블루 색상, 원형 통계, 계좌·분류·거래·정산·빚·정기 내역과 Excel 기능을 유지했다.
- SQLite의 공통 인터페이스로 SQL 업무 로직을 공유하고, 웹에서는 고정 버전 WASM 메모리 DB를 사용한다. 선택한 기기 폴더의 체크포인트로 재시작 상태를 복구한다.
- 기기 저장과 Drive 동기화 상태를 구분했다. 저장 실패 시 현재 메모리를 유지하고 추가 입력을 막으며 재시도·전체 백업을 제공한다. 미전송 변경이 있으면 상단 구름 아이콘도 전송 대기로 표시한다.
- Google 웹 토큰 모델을 사용하고 계정·폴더를 기억한다. 인증 만료 시 사용자가 동기화 버튼을 눌러 재연결한다. Drive 계정 검증과 일반 폴더 선택, 변경 이력 병합·충돌 처리는 유지했다.
- 변경 후 자동 동기화 타이머를 제거했다. 앱 새 실행의 1회 동기화와 수동 버튼만 남겼다. 화면 복귀는 정기 내역 생성·로컬 저장만 수행한다.
- 명시적 기기 데이터 삭제와 브라우저 설치·웹 업데이트 버튼, 오프라인 정적 파일 캐시를 추가했다. 폴더 파일은 평문이며 네이티브 생체인증 잠금은 제공하지 않는다.
- GitHub Actions를 웹 검사·빌드·Pages 배포로 교체했다. 개인 토큰·Drive 폴더 ID·Android 서명·Desktop secret을 빌드에 넣지 않는다.

## 코드 정리

EXE/APK 업데이트 검사기, Inno Setup 스크립트, 네이티브 패키징·릴리스 버전 스크립트, 해당 전용 테스트를 제거했다. Google 네이티브 인증·보안 저장소·생체인증·URL 실행·패키지 버전 플러그인 의존성도 제거했다. 공통 저장소와 업무 함수를 새 웹 코드로 복제하지 않았다.

`database_native.dart`와 인증 테스트용 구현은 기존 단위/위젯 테스트 실행에 사용한다. Android/Windows 프로젝트 디렉터리는 이전 프로젝트 이력으로 남기며 현재 공식 배포 경로에 포함하지 않는다. 새 서버, 장기 토큰 서비스, 상태 관리 프레임워크나 차트 라이브러리는 추가하지 않았다. 브라우저 SQL 테스트를 위해 개발 의존성 `test`를 사용하며 앱 배포에는 포함되지 않는다.

## 검토 중 발견하여 수정한 문제

1. **입력 때마다 Drive 접근:** 타이머와 복귀 시 동기화를 제거하고 새 실행과 명시적 요청만 허용했다.
2. **미저장 상태를 저장 완료로 오인:** 비동기 체크포인트 큐와 쓰기 완료 확인을 추가했다. 쓰기 중 추가된 변경은 다음 저장으로 이어지며 flush는 마지막 저장까지 기다린다.
3. **첫 저장 실패 후 빈 파일 잔류:** 최초 파일 생성 중 실패한 빈 임시 파일만 제거하여 재시도가 가능하게 했다. 이전 정상 체크포인트는 건드리지 않는다.
4. **손상 복구 과정에서 유실 숨김:** 정상 슬롯을 복구할 때 화면에 안내한다. 두 슬롯 모두 손상되거나 최신 스키마인 경우 새 빈 장부로 덮어쓰지 않는다.
5. **기기 재실행 시 충돌·전송 상태 누락:** 사용자용 새 장부 복원과 기기 체크포인트 재개방을 구분했다. 기기 ID·초안·전송 완료 ID·미해결 충돌까지 유지한다.
6. **중복 탭/오래 열린 창:** 같은 브라우저 원본의 Web Lock과 저장 전 파일 지문 검사를 추가했다. 다른 브라우저/외부 프로그램과 같은 폴더의 동시 쓰기는 지원 범위에서 제외했다.
7. **삭제 범위 과대 또는 손상된 백업 잔류:** 선택한 상위 폴더를 재귀 삭제하지 않는다. 앱 식별자 확인 후 알려진 체크포인트와 자동 백업의 엄격한 파일명만 삭제한다. 손상된 자동 백업도 삭제되지만 사용자가 따로 둔 파일과 Drive는 유지한다.
8. **인증 팝업 차단/계정 혼합:** 사용자 클릭 직후 토큰을 요청한다. 잘못된 Google 계정 토큰은 제거하여 다음 버튼에서 재인증할 수 있게 하고 소유자가 다른 계정에 원장을 보내지 않는다.
9. **웹 오프라인 한글 누락:** Noto Sans KR을 OFL 라이선스와 함께 포함하고 CanvasKit과 SQLite WASM을 같은 사이트에서 제공한다.
10. **Windows 개발 서버의 모듈 MIME 오류:** `.mjs`를 text/javascript, `.wasm`을 application/wasm으로 제공하고 오래된 MIME의 조건부 응답 재사용을 막았다. Pages 경로와 동일한 로컬 미리보기 서버를 제공한다.
11. **Flutter Chrome 테스트 호스트 중단:** SDK 테스트 호스트가 존재하지 않는 `#play` 요소에 접근하여 테스트 진입 전 멈추는 것을 확인했다. SDK 자체를 수정하지 않고 SQL/도메인 브라우저 테스트를 공식 `dart test`로 전환했다.

기존 정산 중복 수령, 부모 버전 충돌, 부분 수신, 정기 회차 중복, 과거 분류 문자열 보존, 초기 잔액/이동의 수입 제외 검증도 유지했다.

## 검증 결과

- Flutter 단위/위젯 테스트 **33개 통과**: 가계부 계산, Excel 왕복, Drive 목적지 격리, 버전 충돌·재전송, 체크포인트 복원·실패 재시도·저장 큐·동기화 시점, 344/690/1280 화면과 폴드 너비 전환.
- JavaScript 파일 저장 테스트 **11개 통과**: 교대 저장, 첫 쓰기/이후 쓰기 실패, 체크섬, 한쪽/양쪽 손상, 미래 형식 거부, 오래된 기록 덮어쓰기 차단, 앱 소유 확인 및 삭제 범위.
- 실제 Chrome의 Dart 브라우저 테스트 **2개 통과**: SQLite WASM에서 한글·32비트를 넘는 원화 금액·정산 부담 금액·계좌 이동·체크포인트 재개방·JSON 백업 복원.
- Dart 정적 분석 통과, Flutter Web release 빌드 및 GitHub Pages 하위 경로/오프라인 캐시 패키징 통과.
- 로컬 브라우저에서 시작 화면·폴더 연결 안내, 두 번째 창의 중복 실행 차단, 미리보기 서버를 중지한 뒤 캐시된 시작 화면의 재실행을 확인했다. 실제 사용자 폴더를 선택하거나 Google 계정에 연결하지 않았다.

## 실계정·실기기에서 남은 확인

자동 테스트는 실제 파일 권한 UI와 Google 서비스 승인을 대신하지 않는다. Fold/가로 태블릿/Windows의 실제 폴더 선택·권한 재허용·PWA 설치와 제거, 실제 Google 계정의 두 기기 왕복·권한 만료, 실제 Pages 두 버전 업데이트·오프라인 재실행은 배포 설정과 대상 기기에서 확인해야 한다. Git push, Actions 배포, Google Cloud 설정은 이 작업에서 수행하지 않았다.

앱 제거 시 외부 폴더 자동 삭제와 영구 무인 로그인을 보장할 수 없다는 제약은 해소된 것으로 표시하지 않았다. 변경 이력이 커지면 전체 체크포인트 비용이 늘어나며, 대용량 성능·암호화·이력 압축은 후속 항목이다. 초기 기획의 고급 가져오기/리포트 등 기존 미구현 항목은 README에 유지했다.
