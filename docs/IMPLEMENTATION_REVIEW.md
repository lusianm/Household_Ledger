# 구현 검토 기록

2026-10-13. 구현 범위와 실행 방법은 `README.md`, 최초 기획은 `DEVELOPMENT_PLAN.md`를 기준으로 함께 확인한다.

## 구조

- 화면은 `ui`, 원 단위 계산·제약은 `domain`, SQLite·엑셀은 `data`, OAuth·Drive는 `sync`에 둔다. 화면에서 계좌 잔액을 별도로 저장하지 않는다.
- Flutter 기본 카운터 예제와 예제 테스트를 제거했다. 실제 앱에 테스트용 거래를 생성하지 않는다.
- 화면 공통 선택 입력·확인·금액 표시·도넛 그리기는 공통 위젯으로 묶었다. 별도의 상태 관리 프레임워크·차트 라이브러리·코드 생성 ORM은 추가하지 않았다.
- 테이블 행별 동기화 대신 연결된 금전 기록의 원자성을 유지하는 버전 묶음을 사용한다. 사용하지 않는 서버·웹 프로젝트는 만들지 않았다.
- 버전 확인·배포 메타데이터 검증·다운로드는 `updates/app_updater.dart`로 분리한다. GitHub Actions에서만 설치 EXE를 만들며 로컬 Inno Setup 설치와 Windows ZIP 배포를 요구하지 않는다.

## 검토 중 수정한 문제

1. **정산금 중복 수령:** 수령을 원지출 버전에 포함한다. 두 기기가 같은 잔액을 모두 받았다고 기록하면 합산하지 않고 충돌로 표시한다.
2. **부분 수신:** 새 계좌가 아직 도착하지 않은 정산·환불·빚은 전체 묶음의 금전 반영을 보류한다. 관련 없는 로컬 입력은 계속 허용한다.
3. **백업 후 정기 중복:** 새로운 장부로 복원해도 이미 존재하는 규칙·회차를 확인한다. 거래일 변경과 원래 예정일을 분리해 중복 생성이나 회차 충돌을 방지한다.
4. **기기 시계 차이:** 마지막 수정 시각으로 덮어쓰지 않는다. 부모 변경 관계와 공통 버전을 사용한다.
5. **자동 생성 중복:** 같은 회차를 두 기기에서 생성해도 같은 내용 ID를 만들고 한 번만 반영한다. 삭제·건너뛰기는 이력에 남긴다.
6. **오래 열린 수정 폼:** 편집 중 원본이 바뀌면 저장을 거부하고 다시 열도록 안내한다. 엑셀도 기준 버전으로 같은 검사를 한다.
7. **과거 카테고리 변형:** 분류 이름 변경·삭제나 단순 메모 수정이 과거 분류 문자열을 변경하지 않도록 한다.
8. **초기 자산과 이동의 수입 오인:** 초기 잔액·조정·이동·빚 원금·정산금을 생활 수입/지출 배분 테이블에서 제외한다.
9. **동일 날짜 빚 이벤트:** 원금·상환의 입력 순서를 유지해 정렬 구현에 따른 잘못된 초과 상환 판정을 방지한다.
10. **기기 인증의 재진입:** 잠금 설정 인증 중 앱 복귀가 중첩 인증을 유발하지 않도록 보호한다.
11. **손상된 업데이트 파일:** 저장소·태그·파일명에 맞는 HTTPS 주소만 허용하고 크기와 SHA-256을 검증한다. 실패한 부분 파일은 제거하며 검증된 파일만 시스템 설치 화면에 전달한다.
12. **다른 키로 Android 덮어 설치:** 정식 태그 빌드는 서명 설정을 필수로 하고 디버그 앱에는 자동 업데이트를 제공하지 않는다. 배포 버전과 태그를 일치시키고 빌드 번호 증가를 검사한다.
13. **업데이트 중 장부 유실:** 설치 전 JSON 백업을 저장하고 앱 설치 폴더와 장부 폴더를 분리한다. Windows 설치 식별자를 유지한다. 실제 두 버전 설치를 통한 데이터 보존 검증은 별도로 남아 있다.

## 검증

- 금액·환불·카테고리 이력·월말/윤년·미래 내역·복원·엑셀 왕복·두 기기 충돌·업로드 응답 유실·부분 수신에 대한 도메인 테스트.
- 344 / 690 / 1280 논리 픽셀에서 홈과 모든 탭, 실제 정산·빚·정기 내역이 있는 화면, 입력 중 너비 변경, 저장 후 초안 제거를 검증하는 위젯 테스트.
- 자동 테스트 29개 통과. 업데이트 버전 비교, 초안·낮은 버전 제외, 배포 주소·체크섬 검증, 일일 확인·수동 재시도·캐시, 손상·잘림·과대 파일 차단을 포함한다. Dart 정적 검사도 통과했다.
- Windows 릴리스 빌드·실행 번들 준비와 Android ARM64 디버그 APK 빌드 통과. Android 빌드에는 플러그인의 향후 Kotlin 전환 안내가 있으나 현재 고정 Flutter 버전에서는 빌드에 성공한다.
- GitHub workflow YAML과 포함된 PowerShell 스크립트 문법 확인. 설치 EXE 컴파일, 서명된 APK, 실제 Release 생성은 GitHub에서 미실행이다. 로컬 Inno Setup은 설치하지 않았다.
- 실제 Google OAuth·Drive 연결과 실물 기기 인증은 자동 테스트로 대체하지 않는다. 발급된 클라이언트 설정과 기기에서 별도로 확인한다.

## 남은 범위

자동 테스트가 실제 금융기관 연동을 검증하는 것은 아니며 은행 연동 자체가 최초 범위에 없다. 현재 변경 이력은 압축하지 않으므로 장기 대용량 이력의 성능은 후속 측정이 필요하다. 최초 기획 중 고급 가져오기·리포트 옵션 등 구현하지 않은 항목은 README에 명시했다. 공개 배포 전 Google OAuth, Android 릴리스 서명, 실물 Fold·태블릿 검증이 필요하다.
