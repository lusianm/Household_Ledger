# 차곡

Android 폴더블·가로 태블릿과 Windows PC용 개인 가계부입니다. Flutter Web PWA로 실행하며, 기기의 선택 폴더에 저장하고 본인의 Google Drive 폴더와 동기화합니다. 한국어·원화·Asia/Seoul을 기준으로 합니다.

## 사용 방법

1. 배포된 HTTPS 주소를 최신 Android Chrome 또는 Windows Chrome/Edge에서 엽니다. 저장 폴더 접근 API를 지원하지 않는 브라우저에서는 안내 화면이 나옵니다.
2. **저장 폴더 선택**을 누르면 그 안에 `ChagokLedger` 폴더가 생깁니다. 다른 기기·브라우저와 이 로컬 폴더를 직접 공유하지 마세요. 기기마다 별도 폴더를 사용합니다.
3. 계좌를 등록하고 내역을 입력합니다. 폴드를 접거나 펼쳐도 화면 폭에 맞춰 배치하며 주요 탭은 하단에 있습니다.
   금액은 숫자만 입력하며 `10,000`처럼 천 단위 쉼표가 표시됩니다. 저장하면 해당 월의 내역 목록을 갱신하고 최신 날짜순 정렬을 유지합니다. 저장하거나 클릭한 내역은 시안블루로 강조합니다. 검색어는 해제하고, 저장한 거래가 포함되지 않는 계좌 필터만 해제합니다. 월·필터·탭을 변경하면 선택 강조를 해제합니다.
4. 더보기 → 설정에서 **내 Google Drive 연결**을 누르고 자신의 계정과 폴더를 선택합니다. 다른 기기는 같은 Google 계정·Drive 폴더·가계부를 선택합니다.
5. 브라우저 메뉴 또는 설정의 **앱 설치**로 설치합니다. 설치 버튼을 제공하지 않는 브라우저는 자체 메뉴를 사용합니다.

앱을 새로 열 때 유효한 토큰이 있으면 한 번 동기화하고, 그 외에는 **지금 동기화** 버튼을 눌렀을 때만 동기화합니다. 입력 직후·화면 복귀·백그라운드에서는 동기화하지 않습니다. 기기를 바꾸기 전에 동기화 버튼을 눌러 주세요. 실패한 전송은 다음 수동 동기화에서 재시도합니다.

Google 계정과 폴더는 기억합니다. 단기 액세스 토큰은 브라우저 세션에서 재사용하며, 만료되었거나 세션이 종료되면 버튼을 눌러 다시 연결해야 합니다. Google 로그인 세션이 유지되면 일반적으로 비밀번호를 다시 입력할 필요는 없지만, 매번 무인 로그인되는 것은 보장하지 않습니다. 서버·장기 refresh token·클라이언트 secret은 사용하지 않습니다.

## 저장과 삭제

내역의 금액 아래에는 해당 거래 직후의 계좌 잔액을 표시합니다. 이전 월·검색에서 숨겨진 거래까지 반영하며 수정·삭제·동기화 후 다시 계산합니다. 전체 목록의 이동은 받은 계좌의 잔액만, 계좌별 목록은 선택한 계좌의 잔액만 `○○원`으로 작게 표시합니다. 날짜와 시간 모두 최신순으로 표시하며, 시각은 가져온 메모 맨 앞의 `HH:mm` 또는 `HH:mm:ss`를 사용합니다. 시각이 없는 내역은 같은 날의 시각이 있는 내역 아래에 고유 ID 기준으로 표시하고 초기 잔액은 마지막에 표시합니다. 잔액은 표시 순서의 역순으로 계산하며 동기화 파일에 중복 저장하지 않습니다.

이동과 정기 이동에도 대분류·소분류를 선택할 수 있습니다. 기본 분류는 **저축 → 예금·적금**이며, 더보기 → 카테고리의 **이동 카테고리**에서 추가·수정·삭제합니다. 이동 분류는 선택 사항이며, 분류명과 선택한 ID는 JSON 동기화·Excel 내보내기/가져오기에서도 유지됩니다. 분류를 지정해도 이동은 수입·지출 집계에 포함되지 않습니다.

| 위치 | 저장 내용 |
| --- | --- |
| 선택 폴더/ChagokLedger/owner.json | 앱 폴더 식별자 |
| checkpoint-0.json / checkpoint-1.json | 변경 이력·기기 설정·초안·전송 상태를 담은 교대 체크포인트 |
| backups/before-restore-*.json | 복원 직전 자동 백업 |
| 브라우저 IndexedDB | 폴더에 다시 접근하기 위한 핸들 |
| 브라우저 sessionStorage | 만료 시각이 있는 단기 Google 토큰, 창 세션 종료 시 소멸 |
| 선택한 Google Drive 폴더 | 가계부 메타정보와 불변 변경 JSON |

파일을 번갈아 저장하고 체크섬을 검사하여 마지막 정상본을 보존합니다. 저장 중에는 진행 상태를 표시하며, 저장 실패 시 추가 입력을 막고 재시도·전체 백업을 제공합니다. 경고가 나오면 창을 닫지 말고 먼저 재시도하거나 백업을 내보내 주세요. 폴더 접근 권한이 만료되면 시작 화면에서 기존 폴더를 다시 연결합니다.

**PWA를 제거한다고 선택 폴더가 자동으로 삭제되지는 않습니다.** 제거 전에 설정의 **이 기기의 데이터 삭제**를 사용하세요. 앱 소유 체크포인트와 자동 백업을 삭제하며, Google Drive 파일·상위 폴더·사용자의 다른 파일·직접 내보낸 Excel/JSON은 유지합니다. 식별용 `owner.json`과 관련 없는 파일은 남습니다. 계정 연결 해제는 로컬 장부를 삭제하지 않습니다.

JSON은 암호화되지 않습니다. 기기 잠금으로 보호하세요. 브라우저의 모든 사이트 데이터 삭제는 폴더 연결 정보와 로그인 상태를 지우지만, 사용자가 선택한 폴더의 원장은 그대로 남습니다. 앱 파일 캐시는 제거될 수 있어 다시 온라인으로 접속해야 합니다.

## 제공 기능

- 수입·지출·이동, 은행·현금·적금·카드, 초기 잔액·잔액 조정, 계좌별 내역, 검색, 복사·수정·삭제·부분 환불, 계좌 보관.
- 대분류 → 선택적 소분류, 바로 아래 작은 메모 입력. 분류 추가·변경·삭제. 과거 분류 문자열과 선택적 ID 보존.
- 월간·연간 통계, 대분류·소분류 도넛 그래프, 월별 수입·지출, 월간 전체 예산.
- 사람별 정산과 일부 수령·취소. 정산금은 수입으로 계산하지 않습니다.
- 빌린 돈·빌려준 돈, 추가 원금·부분 상환·취소·기한. 선택적으로 실제 계좌와 연결하며 빚 장부를 보유 자산에 더하지 않습니다.
- 수입·지출·이동의 월간·연간 정기 내역. 적금 납입은 계좌 이동이며 지출 통계에서 제외합니다. 예정일이 지난 회차는 앱 실행/복귀 시 생성합니다.
- JSON 전체 백업·복원, Excel/CSV 가져오기·내보내기, 오프라인 변경 병합·충돌 선택.

| 기록 | 계좌 잔액 | 생활 수입·지출 |
| --- | --- | --- |
| 일반 수입/지출 | 증가/감소 | 반영 |
| 계좌 이동/적금 납입 | 출발·도착 계좌 반영 | 제외 |
| 공동 결제 | 전액 차감 | 본인 몫만 지출 |
| 정산금 수령 | 증가 | 제외 |
| 빚 원금/상환 | 계좌 연결 시 반영 | 제외 |
| 환불 | 증가 | 환불일 지출 차감 |
| 초기 잔액/조정 | 반영 | 제외 |

전체 보유 금액은 현금·은행·저축 잔액 합계입니다. 받을 정산과 빚 원금은 더하지 않습니다. 카드 사용은 지출, 카드대금 납부는 은행에서 카드로 이동으로 기록합니다.

## GitHub에 설정할 내용

기존 Android 서명 키, Desktop client secret, Inno Setup 설정은 웹 배포에 필요하지 않습니다. 삭제 여부와 관계없이 새 워크플로는 해당 Secrets를 읽지 않습니다.

1. Google Cloud 프로젝트에서 **Google Drive API**를 활성화합니다.
2. Google Auth Platform의 Branding/Audience/Data Access를 설정합니다. 개인 테스트 단계에서는 자신을 테스트 사용자로 등록합니다. 사용자 임의 폴더를 탐색하므로 `https://www.googleapis.com/auth/drive` 범위를 사용합니다. 공개 이용에는 Google의 동의 화면 및 제한된 범위 검증 요건을 확인해야 합니다.
3. OAuth 클라이언트 유형을 **웹 애플리케이션**으로 만듭니다. 승인된 JavaScript 원본에 `https://lusianm.github.io`를 등록합니다. 다른 계정/도메인으로 배포하면 그 원본으로 바꿉니다. 원본에는 `/Household_Ledger/` 경로를 붙이지 않습니다. 팝업 토큰 모델이므로 앱 콜백 페이지나 client secret은 사용하지 않습니다.
4. 저장소 **Settings → Secrets and variables → Actions → Variables**에 `GOOGLE_WEB_CLIENT_ID`를 추가합니다. 값은 웹 클라이언트 ID입니다. 이 값은 공개되어도 되는 앱 식별자이며 개인 Google 계정 정보가 아닙니다.
5. **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
6. 코드를 `main`에 push하거나 Actions의 **Verify and deploy web app → Run workflow**를 실행합니다. 검증·빌드 성공 후 Pages에 배포됩니다.
7. 예상 주소는 `https://lusianm.github.io/Household_Ledger/`입니다. 실제 배포 주소는 Actions의 `github-pages` 환경에서 확인합니다. 로컬 작업만으로 이미 게시되었다고 간주하지 마세요.

`GOOGLE_WEB_CLIENT_ID`가 비어 있어도 로컬 가계부 빌드·사용은 가능하지만 Google 연결은 사용할 수 없습니다. 개인 토큰, 계정 이메일, Drive 폴더 ID, 장부 파일을 GitHub 설정이나 Git에 넣지 마세요. 모든 이용자는 앱에서 자기 계정으로 로그인합니다.

업데이트는 같은 웹 주소에 새 빌드를 배포하면 됩니다. 설정의 **업데이트 확인**을 눌러 새 버전을 준비하고 저장이 끝난 후 적용합니다. 앱 제거·재설치는 필요하지 않습니다. 정적 파일만 오프라인 캐시하며 Google 인증·Drive 응답은 캐시하지 않습니다.

## 개발 및 검증

Flutter **3.47.7**, Node.js **22 이상**을 사용합니다. SQL 패키지와 WASM은 **3.7.0**으로 고정하고 준비 스크립트에서 공식 배포의 SHA-256을 확인합니다.

```powershell
node scripts/prepare-web.mjs
flutter pub get
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
dart test --platform chrome test/browser/wasm_test.dart
node --test test/web_storage_test.mjs
flutter build web --release --no-web-resources-cdn --pwa-strategy=none --base-href /Household_Ledger/ --dart-define-from-file=config.local.json
node scripts/package-web.mjs
```

`config.example.json`을 `config.local.json`으로 복사하고 본인의 웹 클라이언트 ID를 넣습니다. Google 연결 없이 확인할 때는 `--dart-define-from-file` 옵션을 생략합니다. 개발 서버의 원본(예: `http://localhost:8080`)도 Google에 등록해야 합니다. 폴더 선택은 HTTPS 또는 localhost 보안 컨텍스트가 필요합니다.

`build/web`가 배포 결과입니다. 루트 주소에서 테스트할 때는 `--base-href /`로 빌드합니다. 프로젝트 경로 배포를 로컬에서 재현하려면 아래 서버를 사용합니다.

```powershell
python scripts/serve-web.py --port 8080
```

브라우저에서 `http://localhost:8080/Household_Ledger/`를 엽니다. Flutter 개발 서버만 실행한 결과에는 최종 오프라인 캐시 패키징이 없으므로, PWA 설치·업데이트 검증에는 위 release 결과를 사용합니다.

`lib/data`는 SQL·체크포인트·Excel, `lib/domain`은 금액·업무 규칙, `lib/sync`는 계정별 Drive, `lib/platform`과 `web`는 폴더·인증·PWA를 담당합니다. Android/Windows 프로젝트 디렉터리는 기존 네이티브 프로젝트 이력으로 남겨 두었으며 현재 배포·인증 지원 대상은 웹입니다. 설치 파일 업데이트 코드, 패키징 스크립트와 네이티브 인증 의존성은 제거했습니다.

이전 설치형 앱의 내역은 그 앱에서 JSON 전체 백업을 내보내고 웹 앱의 백업 복원으로 가져옵니다. 원래 숨김 앱 데이터 폴더를 사용한 경우에는 이전 앱에서 먼저 내보내세요. 웹 앱이 기존 앱의 보안 저장소나 SQLite 파일에 자동 접근하지는 않습니다.

## 검증 범위와 남은 확인

실제 결과는 [구현 검토](docs/IMPLEMENTATION_REVIEW.md), 위험·제약은 [웹 전환 설계](docs/WEB_TRANSITION.md)에 기록합니다. Google OAuth/Drive 실계정 왕복, 실제 Fold·태블릿의 폴더 선택 및 PWA 설치/제거, 실제 Pages의 연속 두 버전 업데이트는 배포 설정과 실기기에서 확인해야 합니다.

초기 기획 중 사용자 지정 Excel 열 매핑, 분류 수동 정렬, 기존 입금과 정산 연결, 계좌별 리포트 필터·그래프에서 원거래 이동, 분류별 예산은 후속 항목입니다. 현재는 고정 열 가져오기·정산 전용 입금·월간 전체 예산을 제공합니다. JSON 암호화와 장기 변경 이력 압축도 후속 설계입니다.

한 로컬 폴더를 여러 브라우저 프로필이나 외부 동기화 프로그램에서 동시에 편집하는 것은 지원하지 않습니다. 같은 사이트의 두 창은 잠금으로 차단하고 디스크의 사전 변경은 감지하지만, 다른 프로세스와의 파일 쓰기를 원자적으로 잠그는 OS 잠금은 웹에서 제공하지 않습니다. Pages의 같은 사용자 도메인에 있는 프로젝트는 브라우저 보안상 같은 원본이므로 신뢰할 수 없는 앱과 함께 배포하지 않도록 주의합니다.

오프라인 한글 글꼴은 Google Fonts의 Noto Sans KR이며 [OFL 라이선스](assets/fonts/OFL.txt)를 포함합니다.
